# Как снять видео-демо AuditGym

> Инструкция для человека, который записывает видео. Устанавливать ничего не нужно: сайт и живая
> среда уже работают по адресу **https://auditgym.byapex.dev**.

**Формат:** 3:30–4:00 · 1920×1080 · русский язык · голос + экран · субтитры RU/EN по желанию.
**Главный тезис:** мы построили **экзамен для ИИ-аудитора**, а не самого аудитора. Компания
выдуманная, ошибки спрятаны намеренно, проверяющий честно ставит оценку, и его нельзя обмануть.
**Фраза, которую жюри должно запомнить:** «Среда генерирует синтетический месяц бухгалтерии,
прячет в нём ошибки и оценивает, нашёл ли агент их с доказательствами».

**Что должно быть доказано в кадре:**

1. Среда создаёт целый месяц бухгалтерии выдуманной компании из одного числа (seed).
2. В данных намеренно спрятаны ошибки четырёх типов, и есть похожие, но правильные операции.
3. Агент видит только то, что запросил, и каждый шаг стоит части бюджета.
4. Отдельный проверяющий сравнивает ответ с ключом и считает награду по формуле организаторов.
5. Обмануть оценку нельзя: «обвинить всё» даёт минус.
6. Всё воспроизводится одной командой без интернета и без обученной модели.

## 1. Контекст: что такое AuditGym

AuditGym — воспроизводимая среда для тренировки и проверки ИИ-финансового аудитора. Генератор
создаёт выдуманную компанию **NorthAngels FoodService Ltd.** (оптовые поставки и доставка еды для
HoReCa и независимых трейдеров; модель бизнеса вдохновлена публичной отчётностью METRO AG) и один
календарный месяц её бухгалтерии. В записи намеренно вносятся ошибки. Агент читает книги через
пять инструментов только на чтение, а отдельный проверяющий сравнивает его находки с ключом
ответов и считает официальную награду.

- **Хакатон:** кейс FinTech «RL environments for fine-tuning financial audit models», онлайн-этап
  19–22 ноября 2026, сдача 22.11.2026 в 23:59 по Астане.
- **Что сдаётся:** среда, а не обученная модель. Веса не обучаются, улучшение модели не
  заявляется.
- **Команда:** Айбек (`Aibek-S`) — генератор, ошибки и ключ ответов, среда, оценщик, runner;
  Мейірбек (`mmeirbek`) — лендинг, консоль и демо.
- **Публикации:** 20 эпизодов (`episodes/train` seed 1001–1010 и `episodes/dev` seed 2001–2010),
  48 ошибок, 6 чистых месяцев, 6 комбинированных сценариев, 126 тестов.
- **Лицензия:** MIT. **Репозиторий:** https://github.com/Aibek-S/auditgym.

## 2. Словарь: как объяснять термины простыми словами

| Термин | Простыми словами |
|---|---|
| Эпизод | Одна выдуманная компания и один месяц её бухгалтерии. |
| Среда | Программа, которая выдаёт агенту наблюдения и принимает действия. |
| Агент (политика) | Код, который решает, что запросить дальше, и в конце отправляет находки. |
| Шаг | Один вызов инструмента. Ошибка тоже тратит шаг. |
| Наблюдение | Ответ среды: строки журнала, документ, курс, результат вычисления. |
| Ключ ответов (truth) | Список настоящих ошибок с суммой и доказательствами. Агенту недоступен. |
| Проверяющий (evaluator) | Отдельная часть, которая сравнивает ответ с ключом и считает награду. |
| Seed | Одно число, из которого полностью воспроизводится месяц. |
| Внесённые ошибки (plan) | Принудительный набор ошибок для демонстрации. |
| Чистый месяц | Тот же месяц без ошибок; правильный ответ — пустой список. |
| Ловушка (distractor) | Правильная операция, похожая на ошибку: повторный заказ, оплата частями, возврат. |
| Доказательства (evidence) | Id документов и проводок, которые подтверждают находку. |
| Open / closed | В открытом режиме агент видит награду после отправки, в закрытом всегда видит 0. |

Формула награды, которую надо показать на экране и назвать вслух:

```
R = clip(2·F1 − 1 − 0.002·S, −1, 1)
```

где `F1` — качество находок, `S` — число шагов проверки до отправки. Отправка бесплатна.

## 4. Подготовка до записи (10 минут)

1. Браузер Chrome или Edge. Окно на весь экран, масштаб страницы 100% (`Ctrl+0`).
2. Закройте лишние вкладки и уведомления, включите режим «Не беспокоить», уберите панель
   закладок.
3. Откройте три вкладки:
   - `https://auditgym.byapex.dev` — лендинг;
   - `https://auditgym.byapex.dev/console/live` — живой прогон;
   - `https://github.com/Aibek-S/auditgym` — репозиторий (на случай вопроса жюри).
4. На живой странице выберите язык **RU** и сделайте пробный запуск (кнопка «Запустить агента»).
   Дождитесь надписи «terminated», убедитесь, что шаги появляются по одному. Затем нажмите
   «Новый эпизод» — это очистит экран для записи.
5. **Правило настроек:** seed, тип ошибок, режим и агента выбирайте **до** нажатия «Запустить
   агента» или «Новый эпизод». Кнопка «Новый эпизод» сразу создаёт эпизод с текущими настройками.
6. Проверьте звук: 30 секунд пробной записи, микрофон не клипует, нет эха.
7. Запись экрана: OBS Studio (бесплатно), `Win+Alt+R` в Windows или `Cmd+Shift+5` на Mac.
   Разрешение 1920×1080, 30 или 60 кадров в секунду, курсор виден.
8. Держите перед глазами раздел 8 (точные цифры) — там всё, что нужно называть.

**Настройки живой страницы для записи:**

| Поле | Значение |
|---|---|
| Seed | `2004` |
| Внесённые ошибки | «Комбинация I1: валютный счёт на границе» |
| Агент | `reconcile` |
| Режим | «Открытый» |
| Скорость | «Медленно» (для записи; «Обычно» — для репетиции) |

## 9. Чего не говорить и не делать

- Не говорить «модель научилась аудиту» или «мы обучили модель»: веса не обучались, сравнения

- Не смешивать демо-архив (7 эпизодов, 8 ошибок) и опубликованный сплит (20 эпизодов, 48 ошибок).
- Не нажимать «Новый эпизод» много раз подряд: лимит 20 новых эпизодов в минуту.
- Не оставлять в кадре личные вкладки, почту, уведомления.

## 10. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| «Живая среда не запущена» | Обновить страницу через 10 секунд. Если не помогло — сообщить Айбеку |
| «too many new episodes; wait a minute» | Подождать минуту и продолжить |

## 13. Для Айбека: сервер и деплой

### Как устроено

- Домен: **https://auditgym.byapex.dev** (Cloudflare).
- Сервер: `xboing`, код в `~/projects/auditgym`, сайт и API на `127.0.0.1:8765`.
- Наружу — Cloudflare Tunnel, службы `auditgym` (сайт + API) и `auditgym-tunnel`.
- Статика и API на одном адресе: `/` и `/console` — собранный сайт, `/api` — Python-сервер.

### Проверка

```bash
curl -s https://auditgym.byapex.dev/api/health          # {"ok":true,"scored":true}
for p in / /console /console/live; do
  curl -s -o /dev/null -w "$p %{http_code}\n" "https://auditgym.byapex.dev$p"
done                                                     # все 200
ssh xboing 'systemctl --user status auditgym auditgym-tunnel --no-pager | head -20'
ssh xboing 'journalctl --user -u auditgym -n 50 --no-pager'
```

### Обновление

```bash
# локально: пересобрать сайт после правок во фронтенде
cd ~/projects/hackathon-genesis/web && npm ci && npm run build

# скопировать на сервер
cd ~/projects/hackathon-genesis
rsync -a auditgym/ xboing:~/projects/auditgym/auditgym/
rsync -a deploy/   xboing:~/projects/auditgym/deploy/
rsync -a --delete web/dist/ xboing:~/projects/auditgym/web/dist/

# перезапуск нужен только если менялся Python-код
ssh xboing 'systemctl --user restart auditgym'
```

Статические файлы подхватываются без перезапуска; `index.html` отдаётся с `no-cache`,
у собранных ресурсов новые имена, поэтому старый кэш не мешает.

Документация (`docs/`) на сервере не раздаётся, поэтому правки гайда деплой не требуют.

### Лимиты демо-сервера

24 сессии, 30 минут жизни сессии, 4 одновременных потока, 20 новых эпизодов в минуту на адрес.
Папки эпизодов удаляются автоматически.

## Приложение A. Типы ошибок и комбинации

| Тип | Суть | Что ломается |
|---|---|---|
| `duplicate_invoice` | Копия счёта с новым id, та же накладная и строки | Выручка и дебиторка завышены |
| `payment_allocation` | Платёж покрывает счёт не полностью, остаток уходит в 1900 | Счёт ложно открыт |
| `fx_conversion` | Пересчёт по курсу не той даты (предыдущий день, UTC вместо локального) | Сумма в KZT неверна |
| `period_cutoff` | Выручка проведена не в том периоде | Выручка в чужом месяце |
| I1 | Валютный счёт на границе периода: сдвиг периода + неверный курс | Две ошибки в одном счёте |
| I2 | Дубль счёта + неполное разнесение оплаты | Две ошибки, связанные цепочкой |

Ловушки: повторные заказы с той же суммой, корректировки и перевыставления, частичные возвраты,
раздельные и объединённые платежи, недоплаты, переплаты, платежи без ссылки, реализованная
курсовая разница, полуночные отметки в других часовых поясах, крупные иностранные заказы.
